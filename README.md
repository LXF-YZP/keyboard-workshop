## 界面风格（1.6）

使用暖白、炭黑和单一深绿强调色，以细边框划分左侧文件操作、中央画布和右侧属性。控件采用紧凑间距与小圆角，数字、单位、状态和快捷键使用等宽字体。定位板通过线型区分板框、轴孔、模块孔与卫星轴孔；几何检查通过文字标记提示状态。

右侧属性栏随当前标签切换：“固件”显示目标主控、矩阵引脚、层与动作、检查和导出；“配列校正”显示键位属性（含逐键定位板覆盖）和分体镜像；“定位板预览”显示几何检查与导出，以及可折叠的“轴孔与卫星轴 / 键距与板框 / 固定孔与外壳 / 加工 / 模块开孔与圆孔”参数组，组标题右侧显示当前设置。定位板视图的画布工具栏改为“定位板 / 中框 / 底板”图层切换；存在几何错误时，“定位板预览”标签显示错误数。

当前为 **1.6 / 构建 35**。工坊助手已接通工程、截图识别、配列、定位板、完整固件、导出与受管 GitHub 主要流程，支持组合草稿、画布叠图和安全事务撤销；构建 35 优化了视觉行列推断、长请求等待、思考模式兼容及提案修正流程；应用内“操作说明”已新增助手使用教程。

## 快速开始

1. 复制键盘截图后，在软件窗口按 **⌘V（Command + V）**，或点击“粘贴截图”，即可导入并自动识别。macOS 按 **Control + Shift + Command + 4** 可以直接截取到剪贴板；已有截图也可先复制图片。也支持点击“导入键盘截图”，选择 PNG、JPEG、HEIC 等图片。优先使用正上方拍摄、键帽边缘清晰的图片，单张最多 30 MB。

   粘贴文字时，输入框仍按正常方式接收文字。剪贴板没有图片时，“粘贴截图”会显示提示。每次导入新截图会开始新的配列；如果当前已有截图或键位，替换前会自动保存到左侧“配列管理”，可随时切换回来。
2. 需要时勾选画布底部的“参考图”叠图检查键位（默认不勾选）。在画布上方的“键位”组点“新增”，再在画布单击放置 1U 键或拖动描出长键；新增模式会持续保留，按 Esc 返回“选择”。删除时点“选择”后选中按键，再点同组的“删除”或按 Delete / Backspace；Shift 单击可多选。复制与删除只在有选中项时启用，操作完成后回到“选择”；⌘Z 可撤销。键帽文字会在识别键位后自动读取（见下方“键帽文字识别”）；图标键帽和读不清的文字使用编号，可在右侧修改键帽文字。

   **自动校正分体对称（默认开启）**：截图识别阶段检测左右键区及对应关系；检测明确时，每对键使用相同的中心 Y，X 和角度互为镜像，保留列间错位、两侧各自的文字与尺寸。状态栏会显示已对齐的键对数。不对称布局可取消勾选后点击“重新识别截图”；切换开关本身不会修改当前配列。
3. 点击“校准”，依次点同一排相邻两个 **1U 按键的中心**，确定图片中的像素键距；右侧“键距 / mm”填写实物的中心间距，默认 19.05 mm。单张截图无法确定真实毫米尺寸。
4. 在右侧修改每键的中心 X/Y（U）、宽高（U）和角度。顺时针为正，画布 X 向右、Y 向下。Shift 单击多选后，可以整体移动、统一角度或对齐。请重点检查边缘、拇指键和长键。

   **定位板覆盖（仅所选键）**：键位属性下方可把长键设为“不装”卫星轴或“翻转 180°”（卫星轴开孔向北偏移），也可单独旋转轴孔 0° / 90° / 180° / 270°（例如让开盖缺口朝上下）。选中示意标记时可勾选“示意标记参与板框轮廓”，例如让 TPS65 触控板区域扩大板框但不开孔。

   **邻键吸附（默认开启）**：直接把待移动按键拖到邻键的上、下、左或右侧附近，松开时自动采用参考键的角度，并对齐位置、保持相邻键距，无需预先旋转。深绿色虚线框表示参考键，连线表示对齐方向，吸附预览会提示角度校正结果。例如将 6 号键拖到 15 号键上方，两个 1U 键的中心距会固定为 1U，而非重叠。旋转键区沿自身方向对齐，长键按两键宽高计算间距。占用的位置不吸附，示意标记不参与邻键吸附。

   多选时整组平移，保持组内相对位置。按住 **Option（Alt）** 临时关闭所有拖动吸附；底部“邻键吸附”可关闭自动对齐。“网格 0.25U”可独立开启，邻键吸附优先。一次拖动可用 ⌘Z 整体撤销，方向键仍可微调。
5. 点击“导出 KLE”，保存 `.kle.json`。在 [Keyboard Layout Editor](https://www.keyboard-layout-editor.com/) 使用 **Upload JSON** 导入。需要粘贴到网站 **Raw data** 页时，打开“配列数据”，点击“导出 Raw Data”；两种导入方式使用的最外层括号不同。
6. 点击“查看定位板”，在右侧按分组设置，所有尺寸单位为毫米：
   - **轴孔与卫星轴**：MX 14 × 14、MX 开盖缺口（两侧各两个 0.8 × 3.1 mm 缺口，中心距轴心 ±4.45 mm，可不拆板开盖换轴芯）、Choc 13.8 × 13.8、Alps SKCM 15.5 × 12.8、MX / Alps 兼容（两者并集）或自定义方孔。卫星轴可选 PCB 矩形避让 7 × 14（居中）、MX Basic 7 × 15、MX Tight 6.75 × 14、Costar 3.3 × 14.2，或 Cherry Spec 板载式闭合轮廓。Cherry Spec 会把两侧卡扣 / 钢丝通道与轴孔并成一条闭合轮廓，3U 及以上采用较窄通道；内角圆角最高 0.4 mm。卫星轴间距支持 2–2.75U、3U、6.25U、7U、8U；4U、6U 来源数据不一致，需自行确认或设为不装。
   - **键距与板框**：键距 X / Y 可分开填写（Choc 常用 18 × 17 mm），Y 留空时与 X 相同；外框边距、板框圆角和板框类型。
   - **固定孔与外壳**：“自动固定孔”填写每块板的孔数（0 为不生成）、孔径（M2 约 2.2 mm，M3 约 3.2 mm）和孔心距板边。孔沿板框内缩路径放置：先放在转角，孔数多于转角时补到间隔最长的边上；碰到轴孔、卫星轴、模块孔或 USB 开口时沿板边滑开，保留至少 0.5 mm 料厚，放不下会提示。“外壳”选择“三明治”后生成中框（板框向内偏移“中框宽度”形成开口）和底板，固定孔同步到三层；“USB 开口宽”大于 0 时在中框上沿开口，中心 X 留空则居中，分体板框需填写所在一侧的位置。中框开口必须让出所有轴孔、卫星轴和模块孔，否则提示加大外框边距或减小中框宽度。
   - **加工**：“开孔内角 R”给轴孔、卫星轴、模块孔和中框开口的内角倒圆（CNC 铣削常用 0.5 mm，开盖缺口处按 0.8 mm 宽度限制为 0.4 mm）。“板框圆角 R”在“键距与板框”中，凹角同样倒圆，边长不足时自动减小并提示。“切缝补偿”按切缝**总宽**填写（与 swillkb / kle-ng 相同；ai03 填的是单边值），只用于自行激光切割：导出刀路时开孔向内、板框和中框材料向外各偏移补偿值的一半，画布预览和几何检查仍按成品尺寸；加工厂自行补偿时保持 0。
   - **模块开孔与圆孔**：可添加可旋转矩形孔与圆孔；手动圆孔只开在定位板上，需要贯穿外壳的孔请使用自动固定孔。

   **截图键盘轮廓**：在“板框”中选择该项后，可点击“从截图提取”得到截图可见区域的可编辑初始轮廓；截图被裁切、缺边或自动结果不准时，点击“手动描绘”，在画布上逐点单击外沿，接近首点或点击“完成轮廓”闭合。轮廓至少 3 点，支持凹形边界，闭合后随工程和自动保存记录。自动结果只代表截图中可见范围，不能补回被裁掉的真实外壳。
7. 检查右侧“几何检查”。带有“错误”标记的项目代表孔位相交、越界或外壳冲突，修正后点击同一区域下方的“导出 DXF”或“导出 SVG”（唯一导出入口）。默认导出当前图层（文件名后缀 `.plate` / `.frame` / `.bottom`）；启用三明治外壳后可勾选“定位板、中框、底板合并为一个文件”，三层上下排列、间隔 12 mm，文件后缀为 `.case`。
8. 使用“保存工程”保存 `.keyboard.json`，其中包含参考图、配列、开孔和参数，之后可以继续编辑。KLE 文件只保存配列，不保存模块机械开孔。

**键帽文字识别（构建 19）**：键位出现后，忙碌提示显示“正在识别键帽文字 n / 总数”。每个键帽按位置和角度摆正，以多种放大比例和裁切范围读取；系统识别漏掉的小字母、数字和标点再用本机字形对照补读。读数与笔画证据一致才采用，不按 QWERTY 配列猜字。只替换仍是编号的键，按键位身份对应，结果不另占一步撤销：⌘Z 一次即回到识别前。

**按当前键位补读文字**：已经手动校正、增删过键位的配列，点击左侧“识别键帽文字”即可按当前键位中心、尺寸和角度读取截图文字，只填写仍是编号或空白的键，不改动位置，也不覆盖已填写的文字；整次可用 ⌘Z 撤销。需要工程中含有参考截图。截图之外或没有键帽的键位保留编号。本轮两张 42 键截图的字母、键名和五种标点均全部正确；21 个图标负样本没有误填文字。其他图片仍受清晰度、遮挡、字体和透视影响，请叠图校对，必要时在右侧手动修改。Intel Mac 上 42 键约需 6–8 秒，按键越多耗时越长。

识别灵敏度设为“宽松”可保留更多候选，包括与主键区分离的独立键；也会增加误识别。“区域”工具用于限定键盘所在范围，然后重新识别。重新识别会重建键位，并清空手动添加的机械开孔，可用撤销恢复。

自动分体校正需要明显的中央间隔、相近的左右键数及充分明确的几何配对。普通整键盘、单手键区或左右明显不同的布局保留原识别结果；未匹配键不会补造，校正导致重叠时保留原结果。对称位置取两侧识别值的平均。打开已有工程或恢复自动保存时，不会自动执行校正；已有截图工程需主动重新识别，或使用下方手动镜像工具。

## QMK / ZMK 固件（构建 20–25）

每个工程选择一种固件，生成 GitHub 上可编译的源文件仓库。应用不含本地固件编译器；锁定 QMK `0.34.7`、ZMK `v0.3`。2026-10-25 已对用户导出的 `my_board-qmk` 完成本地实际编译，原生 RP2040 双线分体 + 右手 TPS43 成功生成并核验 UF2，记录见 `output/firmware-check-20261025/编译验收报告.md`。那份构建 24 的旧导出基础层 42 键均为 `KC_NO`；构建 25 已自动将识别文字带入第 0 层，用当前工程副本生成的 40 个普通键码及 `MO(1)` / `MO(2)` 已再次实际编译为 UF2，记录见 `output/build25/compile-verification.json`。旧导出目录未被覆盖，使用新键码需重新导出。ZMK、实际 GitHub Actions 和硬件刷写仍未验收。

| 主控预设 | QMK | ZMK |
| --- | --- | --- |
| Pro Micro ATmega32U4 | 支持，导出 `.hex` 的编译流程 | 不支持 |
| 通用 RP2040（原生 GP0–GP29） | 原生 `RP2040 / GENERIC_RP_RP2040`，单体或有线分体，`.uf2` | 不支持 |
| SparkFun Pro Micro RP2040 | `CONVERT_TO=sparkfun_pm2040`，`.uf2` | `sparkfun_pro_micro_rp2040`，仅 USB，`.uf2` |
| nice!nano v2 | 不支持 | `nice_nano_v2`，单体或蓝牙分体，`.uf2` |

1. 打开已有配列，点击“固件”标签，选择 QMK 或 ZMK 及兼容主控。填写显示名称和键盘标识（小写字母开头，只含小写字母、数字、下划线，最长 32 字符）。
2. 选择单体或分体。分体先点击“按中线划分左右手”，也可选中按键手动调整所属侧；点击“自动建议矩阵”，核对每侧实体键行列。展开“手动设置行列”，Shift 按顺序多选后可连续编号；单键可编辑行列。单体建议按 Y 坐标聚类，错列造成长链且超过 18 引脚时改用 0.5U 行带；分体按每侧局部列从上到下编号，右手列方向镜像，拇指键独立成行。建议均需按真实布线核对；连续编号不能同时包含左右手。
3. 按实际接线分配行 / 列引脚及二极管方向。分体在“当前配置侧”切换左手和右手，两侧引脚分别保存，可重复使用相同 GPIO 和局部行列号；同侧重复、缺失或越界会阻止导出。分体行列数均指每侧，两侧目前使用同款主控、相同行列数及二极管方向。通用 RP2040 使用原生 GP0–GP29，需核对实际开发板引出和占用；SparkFun Pro Micro RP2040 的 18 个兼容接口按实际 GP 编号显示和排序（如旧 A0 / 18 对应 GP26）。两种 RP2040 预设之间切换会按 GP 换算，目标板不具备的接口清空后需重选。其余主控按 Pro Micro 接口编号显示。42 键 TPS65 示例在分体下为左右各 21 键、每侧 4×6；单体建议仍为 7×10，允许空位。
4. 启用固件时，已识别的键帽文字会自动带入第 0 层；固件启用后识别、补读或编辑文字，也会补齐尚未设置的键。打开旧工程会补齐空的第 0 层。已有动作及手动设为“无功能”的键保持原设置，文字和键码可一起撤销。未知编号、图标和 Fn 留空；识别确认的数字正常映射，旧截图工程的数字需补读或编辑确认。也可点击“按键帽文字补齐第 0 层”。支持字母、数字、F1–F24、编辑、导航、符号、媒体键和八个左右修饰键。多选后点击“应用到选中键”可批量设置；QMK 不支持同一动作同时组合左右两侧修饰键，此情形会明确报错。
5. Lower / Raise 默认自动映射为 `MO(1)` / `MO(2)`，缺少的层自动创建并以透明动作初始化；已有同名功能层优先复用，不改层名或覆盖该层内容。切到相应层可继续设置导航、符号等动作，Fn 的目标层需手动指定。最多 10 层，支持透明、无功能、MO / TG / TO；新层默认透明。中文层名可保存，导出到固件时转换为 ASCII。被其他层引用的层需先解除引用才能删除；删层后高层引用自动调整。
6. 检查错误与提示，点击条目定位相关按键。“预览文件”可逐文件阅读；“上传 GitHub 并编译”直接上传并自动构建，使用流程见下节。“导出到本地”选择父目录后创建子目录，重名自动增加 `-2` 等后缀，仍包含隐藏 `.github` 工作流和中文 README。

### USB VID / PID

在“固件 → 固件目标”的键盘名称下填写 **USB 厂商 ID · VID** 与 **USB 产品 ID · PID**。例如 VID `0xFEED`、PID `0x0001`；支持 1–4 位十六进制数，可省略 `0x`，失去焦点后自动补齐为四位大写。空值、超过四位或非十六进制内容会显示错误并阻止导出。

两个 ID 随工程、自动保存和配列历史保留，支持撤销重做；切换 QMK / ZMK、单体 / 分体和主手仍保留自定义值。未填写过的旧工程沿用 QMK `0xFEED / 0x0000`、ZMK `0x1D50 / 0x615E`，不自动新增工程字段。QMK 写入 `keyboard.json` 的 `usb.vid / usb.pid`；ZMK 写入 `config/<键盘标识>.conf` 的 `CONFIG_USB_DEVICE_VID / CONFIG_USB_DEVICE_PID`，分体共用这份配置。本地导出和 GitHub 上传均使用这些设置；修改后需重新导出或上传并编译、刷入，已生成的文件不会自动更新。ZMK 的这两个 ID 用于 USB 连接，蓝牙名称和配对标识单独管理。

### 直接上传 GitHub 并编译

1. 在“固件”右侧底部点击 **上传 GitHub 并编译**，再点击“连接 GitHub”。原生安全输入窗口提供“创建访问令牌”入口；登录 GitHub 个人账号，创建 **Personal access token（classic）**，勾选 **repo** 与 **workflow**，复制后回到软件粘贴并连接。令牌仅保存在 macOS 钥匙串，不进入网页、工程文件或导出的仓库；“断开”会移除令牌。
2. 选择“新建固件仓库”，填写英文、数字、短横线或下划线组成的名称，默认勾选“设为私有仓库”。点击“上传并开始编译”后，软件将当前配置的文件快照提交到 GitHub，由已有 Actions 工作流自动编译。截图和本机工程历史不会上传。
3. 对话框每 15 秒刷新一次，最多自动跟踪 1 小时；也可手动“刷新状态”或“打开 GitHub 日志”。关闭对话框不会取消云端编译。再次打开入口可以查看上次编译，配置暂有错误时仍可查状态，但不能上传。应用重启后打开此入口可恢复最近任务的跟踪。
4. 编译成功且产物未过期时，点击“下载固件”保存 `firmware.zip`，解压后按导出 README 刷入。QMK 分体通常两侧刷同一文件，ZMK 分体包内为左右两份。编译失败时通过 GitHub 日志查看原因；Actions 未启用、账号额度或权限问题也会在状态中提示。真实接线与硬件刷写仍需核对。
5. 再次修改配置后，可在仓库下拉框选择由本软件创建、且与当前键盘标识及 QMK / ZMK 目标匹配的仓库，点击“更新仓库并编译”。只更新生成的文件并清理旧的生成文件，保留仓库中的其他文件；不强制覆盖并发提交。其他已有仓库请继续使用本地导出方式。

仓库与最近任务记录位于独立的 `github.json`，不改变配列历史与撤销记录。首次上传需要你自行连接 GitHub；本版使用模拟 GitHub 网络验证流程，尚未以真实账号运行云端编译。

固件画布上方显示当前层动作（“无功能”表示不发送键码），下方显示矩阵位置（单体如 R0 C0，分体如“左 R0 C0 / 右 R0 C0”）。 “未设行列”表示按键尚无矩阵位置，可点击“自动建议矩阵”；引脚列表的“未选 GPIO”表示某行或列尚未指定主控引脚，必须按实际接线选择。自动建议只填写按键行列，不猜测 GPIO 接线或键码。选择、拖动和平移不会改动键位几何。复制键保留所属侧与动作但清空行列；重新识别按原截图坐标匹配相邻键迁移，歧义或未匹配键重新分配；旧工程默认未启用固件。切换 QMK / ZMK 保留中立动作，设为“未启用”会清除当前固件配置，可撤销。

分体通信与参考预设：

- QMK：在“固件 → 左右手与通信 → 通信方式”选择单线半双工或双线全双工。单线只选一个数据 GPIO，两侧同名引脚相连；双线分别选 TX（发送）与 RX（接收），每侧不能相同，按左 TX → 右 RX、左 RX ← 右 TX 交叉连接，并共地。两侧使用相同的 TX / RX 配置编号；电源按硬件设计连接。双线支持通用 RP2040 和 SparkFun Pro Micro RP2040，使用 vendor / PIO，生成 `SERIAL_USART_FULL_DUPLEX`、`SERIAL_USART_TX_PIN` 和 `SERIAL_USART_RX_PIN`；不会同时导出单线 `split.serial.pin`。AVR 的 bitbang 仅支持单线。两侧刷同一固件，USB 固定连接所选主手，导出 `MASTER_LEFT` / `MASTER_RIGHT`；右手全局行号自动偏移每侧行数，左右引脚独立生成。TX / RX 均参与两侧矩阵及触控板占用检查，未选或冲突会阻止导出；不自动猜测第二个 GPIO。模式、引脚支持保存、配列历史和撤销重做；暂切单线会保留未启用的 RX 值，但不占用它。
- ZMK：无线分体使用两块 nice!nano v2，选择连接电脑的 central 侧；生成 `_left` / `_right` 两个 shield、独立 overlay 和两份构建，分别刷入对应半边。RP2040 无蓝牙，不支持此无线分体方案。
- “套用 3x5_3_azoteq 参考配置”：切换 QMK + 通用 RP2040，按当前配列建议左右手和矩阵，设 ROW2COL、每侧行 GP4/5/27/26、列 GP8/9/7/6/28、单线半双工 GP1（套用时会替换双线设置）；启用左手 TPS43、I2C1 SDA GP2 / SCL GP3、400 kHz、旋转 90°。可调整为右手、TPS65 及其他可用 I2C1 引脚。参考每侧只有 5 列，42 键示例多出的第六列 GPIO 会留空，必须按实际接线补齐；参考拇指键编号也需核对。套用可整体撤销，保留当前键位动作。

旧工程打开后保持单体及原接线，需主动切换。TPS65 示意标记不输出；触控板目前仅支持 QMK + 通用 RP2040 分体的 Azoteq IQS5xx（TPS43 / TPS65）预设。参考项目的编码器、屏幕、自定义显示通信、RGB、宏和双功能键暂未生成。硬件接线与实际刷写仍需自行核对。分体单线、双线与兼容板双线示例仓库和可重开的工程位于 `output/build24/firmware-repositories/`，仅使用项目公开示例；其中第六列及双线 RX 的 GPIO 是测试值，不代表用户接线。原单体示例保留于 `output/build20/firmware-repositories/`。

## KLE 异形键（构建 16）

导入带有 `w2` / `h2` / `x2` / `y2` 的 KLE 文件或 Raw Data，可保留 ISO 回车、阶梯 Caps Lock 等复合键。两个矩形合为完整键帽轮廓，凹口不响应点击；拖动、旋转、多选、邻键吸附、左右镜像、撤销重做、工程保存与配列切换均保留形状。可导入 `示例/ISO-异形键.kle.json` 体验。

右侧宽高表示 **主矩形** 的尺寸，X/Y 是主矩形中心，也是轴孔位置；次矩形相对主矩形左上角偏移，外伸部分影响板框与吸附间距。修改宽高时保留次矩形；与原主尺寸一致的次尺寸同步修改，导致形状断开的修改会拒绝且保留原工程。KLE 导出保留四个次形状字段，卫星轴仍按主矩形长轴和尺寸计算。

当前通过 KLE / 工程数据导入复合形状，截图识别仍输出矩形候选；不自动推断异形键。仅支持两个矩形相交或沿一段边相接的连续轮廓，不支持断开的多块形状、任意曲线键帽或形状编辑器。

构建 16 同时修复 WKWebView 在部分缩放比例下不显示键帽文字和对称轴标签的问题，保留原字号与界面风格。

## 配列管理

左侧“当前配列”下拉框就是配列切换入口。点击它会展示当前配列和所有已保存配列；选择某一项后立即恢复对应的截图、识别键位、文字颜色、轮廓、定位板参数和机械开孔，不需要再点击单独的“切换配列”按钮。下拉项中的“当前”表示正在编辑的项目；同名项目会显示版本号以便区分。

配列名称在下拉框下方的“配列名称”输入框中修改，按回车、移开输入框或点击“保存名称”即可保存。导入第二张截图、粘贴新截图或替换截图文件前，软件会先把当前工程自动归档；最多保留 12 个版本，已保存数量显示在“当前配列”右侧。点击名称行右侧的“另存为新配列”会在不替换当前工程的情况下建立一个独立版本，之后可从当前配列下拉框切换回来。

自动保存工程仍位于 `~/Library/Application Support/KeyboardWorkshop/autosave.json`，配列历史单独保存在同目录的 `layouts.json`。旧版只有一个工程对象的自动保存文件仍可直接恢复；浏览器模式会在 `localStorage` 中兼容保存旧格式。列表记录按最近保存时间排序；下拉项只显示配列名称、版本和当前状态，悬浮时显示最后保存时间。过大的历史数据会按最早记录清理，以避免自动保存无限增长。

## 分体键盘左右列镜像校正

在右侧“分体镜像”中，以已经校正好的一侧为基准，修正另一侧对应列。

1. 检查“对称轴 X”（U）。留空时，使用实体键最左和最右中心的中线；示意标记不参与计算。可以手动填写中线位置，选键后画布会显示深绿色虚线中线。
2. 点击“选左侧”或“选右侧”选择整侧。只校正一列时，在画布中用 Shift 多选该侧这一列的键；所选实体键必须位于中线同一侧。
3. 点击“镜像校正另一侧”。目标键中心满足 `目标 X = 2 × 对称轴 X − 源 X`、`目标 Y = 源 Y`；宽高与源键一致，角度取相反数，因此各列的错位和倾角互为镜像。对侧键的文字、颜色和身份保留。
4. 成功后中线固定在输入框中，便于逐列校正；清空输入框可恢复自动中线。一次校正可用 ⌘Z 撤销、⇧⌘Z 重做。工程与自动保存会记录中线；KLE 和 DXF 使用校正后的几何数据。

对应键优先按镜像位置 0.75U 范围内的几何位置匹配。选择完整一侧、左右实体键数量相同、源侧至少 3 键，且其余键均明确配对时，若恰好只剩一对未匹配键，主矩形宽高差各不超过 0.25U，便可找回偏移较远的那一键，不再受 0.75U 距离限制。此规则不依赖编号或文字；只选一列、多处偏移、缺键或尺寸不符时仍需先调整大致位置。

多个候选接近、重复匹配、跨越中线、缺少明确对应关系，或结果造成越界 / 键位重叠时，整次不执行并保留原配列。按钮下方会显示成功数量、是否找回远移键，或“镜像未执行”的具体原因；选择或编辑变化后隐藏旧反馈。镜像按钮按次执行，后续编辑需再次点击；一次可用 ⌘Z 撤销。示意标记、参考图和机械开孔保持原有数据，不会自动生成、删除或镜像机械开孔。

## TPS65 与加工前核对

内置的 42 键示例是此前讨论的相似配列，包含一个 **TPS65 位置标记**。标记尺寸仅用于布局演示，**不是 TPS65 实物的机械开孔尺寸**，不会自动生成模块孔。

拿到模块机械图或实物尺寸后，添加矩形孔并填写真实宽高与中心位置；如需安装孔，可另外添加圆孔。轨迹球和小红点也可用真实尺寸的模块孔与固定孔表达，复杂轮廓需在 CAD 中继续设计。

截图键盘轮廓可以保存截图中可见的凹形边界并在画布上手动补全，但单张照片仍无法确认被裁切部分的真实外壳、厚度或三维曲面。截图中的透视、键帽侧面和阴影也可能导致中心/角度偏差。

DXF 包含二维轮廓，不包含板厚、材料、倒角、螺纹或工艺公差。正式加工前按轴体与卫星轴机械图核对，并先做小样试装。软件的几何检查只检查轮廓关系，不能替代实物配合与强度检查。
